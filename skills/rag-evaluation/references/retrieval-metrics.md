# 检索指标与样本设计

## Recall@k 与证据覆盖

评估 RAG 检索召回 Recall@k 时，先为每个问题标注真正支撑答案的文档或证据片段。多证据问题要说明是命中任一证据还是全部证据才算成功；二者不能混成同一个召回率。MRR 关注首个相关结果的排名，不能替代多证据覆盖指标。比较时同时报告 k、问题数、标注单位和语料版本。

## 分块 chunk 对比

比较分块 chunk 配置时固定文档与问题集，将证据定位在原文位置而不是易变的 chunk ID。检查标题、代码块、表格行和条件说明是否随相关正文一起进入上下文。记录 embedding 实际 token 上限和最终提示预算，避免把更大的输入预算误判为更好的分块策略。
