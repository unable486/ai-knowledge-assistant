# 项目技能

技能为本轮回答提供分析步骤和格式。项目自带 `frontend-debugging`（前端问题定位）和
`rag-evaluation`（RAG 评估）；文件位于项目 `skills/`，由项目维护者管理，不从用户上传的知识库文档中加载指令。

## 使用方式

在聊天输入框选择模式：

| 模式 | 行为 |
| --- | --- |
| 自动 | 按问题与技能名称、描述匹配；可用 `$frontend-debugging`、`$rag-evaluation` 显式点名 |
| 手动 | 可多选，只加载勾选的技能；未勾选时按普通问答发送 |
| 关闭 | 不加载技能 |

`$id` 只在自动模式生效。自动模式可能同时选中多个相关技能，也可能不选；显式点名优先于自动候选。
更改模式或勾选项从下一次发送生效，重试沿用原消息发送时的选择。选择随聊天保存，技能文件仍按当前内容加载，
因此重试不保证使用旧版本正文。

回答下方的“本次技能”面板展示名称、选择原因、内容版本哈希、实际加入提示的参考原文和警告。
原文按纯文本显示。技能过程记录不写入 localStorage，刷新后面板消失；消息和当时的技能选择仍保留。

自动模式加载失败且当前问题没有 `$` 时，会附带警告并继续原有问答流程；手动选择或显式点名的错误不会被静默忽略。
未知技能返回 400，显式选择了已声明冲突的技能返回 409；核心超预算、参考资料无法安全切分等返回 422。
目录、格式或文件读取异常会说明具体原因。输入框目录加载失败时可点击“重新加载”。

## 技能文件与加载

一个技能目录由 `SKILL.md` 和可选的 `references/` 组成：

```text
skills/
└─ my-skill/
   ├─ SKILL.md
   └─ references/
      └─ details.md
```

`SKILL.md` 使用 YAML frontmatter，核心正文写必需的工作步骤，条件性细节通过 Markdown 链接引用：

```markdown
---
name: my-skill
description: 说明适合处理什么问题，以及需要用户提供哪些材料。
---
# 分析步骤

先核对用户给出的事实，再列出可验证的结论和缺失信息。
遇到具体条件时参考[详细规则](references/details.md)。
```

`name` 必须与目录同名，使用小写字母、数字和连字符；`description` 必须是非空文本，最多 1024 字符。
运行时用 `yaml` 解析并校验 frontmatter，这是本次功能唯一新增的依赖。
`metadata.conflicts_with` 可列出不能同时使用的其他技能名称；这是本项目扩展，并非通用技能标准字段。
任一方声明冲突即生效：显式选择互相冲突时拒绝，自动候选互相冲突时跳过并显示警告。

`GET /api/skills` 只返回 `id`、`name`、`description`，不向客户端公开核心正文或参考资料。
`POST /api/chat` 接受 `skillSelection: { mode: 'auto' | 'manual' | 'off', ids: string[] }`，
旧客户端不传该字段时默认自动模式。文本增量之前的 SSE `skills` 事件携带本次使用过程，供前端面板展示。
自动选择使用名称、描述的本地向量相似度和关键词交集，最多补充三个自动候选；这是小型目录的启发式路由，
不是经过大规模标注验证的准确率保证。
问题包含“同时”“并且”“以及”时，自动路由保留原句，并额外检查最多三个分句，以覆盖明确的多意图请求。
显式选择与最终选中总数均最多 20 个；过程记录最多保留 19 条详细警告，额外警告合并成一条汇总。

选中的核心正文整体加入本轮 system 提示。只有核心正文明确链接到的 `references/**/*.md` 才参与参考检索；
这些文件复用文档结构切块和本地 embedding，命中的片段才加入提示。参考索引临时构建，与用户知识库的索引和来源编号隔离。
文件路径会检查目录范围与符号链接；参考文件解析 `realpath` 后仍必须位于本技能的 `references/` 子树内，
不能通过链接读取同技能其他目录或外部文件。单个文件上限为 128 KiB。

## 上下文预算

技能与 RAG 共用本地 `bge-small-zh-v1.5` tokenizer，关闭截断并计入 special tokens；首次使用需要
[下载本地权重](rag.md#首次运行下载-embedding-权重)。以下预算是 BGE 的分词计数，不是 Claude 的计费 token 或上下文窗口计数。

| 内容 | 上限及处理 |
| --- | --- |
| 用于自动匹配的名称与描述 | 512 token，超出则提示缩短描述 |
| 单个技能核心正文 | 3000 token，超出则拒绝，不能截断核心 |
| 技能提示整体 | 6000 token，包含核心、包装和已加入的参考片段；核心合计超出则拒绝 |
| 单个参考片段 | 连同标题前缀最多 512 token，超长不可安全拆结构拒绝 |
| 加入提示的参考片段 | 全局最多四块、每技能最多两块；不够相关或剩余预算不足时整块跳过 |

参考资料的代码、列表、表格保留完整结构，并绑定能识别的显式条件；跨段关联使用启发式规则，不能保证任意隐含语义依赖完整。
不能用字符截断把部分前提冒充完整规则。
核心过大时应把仅在特定条件下需要的细节移到 `references/`；如何组织安全可切的段落见 [切块规则](rag.md#切块保留完整结构与标题路径)。

## 与知识库的边界

技能是受信的方法指导，知识库原文才是回答中 `[S1]` 等引用的事实依据。技能及其参考资料不生成知识库来源编号，
不覆盖应用的证据规则，也不授予执行命令、浏览器操作或读取用户仓库的能力。这个聊天助手只能分析已提供的输入，
不能因加载了技能就声称已在用户环境运行测试或完成修复。

非空知识库返回资料不足时，没有技能则直接给固定提示，不调用生成模型；有技能则可继续分析用户提供的信息，
或给出明确标注的通用建议。涉及知识库中的事实仍必须说明无法确认，不能伪造依据。空库继续支持普通对话。

## 验证与局限

```bash
npm test
npm run eval:skills
npm run eval:retrieval
npm run eval:answers
```

这些默认命令不调用生成 API。当前 52 项单元测试和构建通过，覆盖选择协议、核心完整性、冲突、路径边界、预算、参考片段和前端请求/重试；
`eval:skills` 使用本地 embedding 检查的 12 个手写路由与按需参考场景通过，不能据此承诺真实问题的路由准确率。

原有 24 道检索题的混合检索回归保持 Recall@4 100%、MRR 0.979、nDCG@4 0.985。
28 道答案场景题中，20 道有证据题的原文证据全部召回；8 道无答案题仅 4 道被粗筛拦下，
因此通过粗筛不能证明资料足够回答。完整评估方法见 [评测基线](answer-evaluation.md)。

本轮没有调用真实生成。此前真实抽检遇到上游 403 余额不足，尚未验证模型实际遵循技能、证据与拒答规则的效果；
提示已注入、路由测试通过和证据被召回，都不能替代真实回答的人工核查。
