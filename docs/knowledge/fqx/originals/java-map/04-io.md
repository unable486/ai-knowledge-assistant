# Java > 异常与输入输出

来源：https://fqx.lx.ci/java-map/

程序不只在内存里计算，还会读文件、访问网络和数据库，这些操作都可能失败。异常负责传递失败信息，IO 负责让程序与外部世界交换数据。

# Java > 异常与输入输出 > 异常：把失败沿调用链传出去

来源：https://fqx.lx.ci/java-map/

`try` 中执行可能失败的代码，`catch` 处理能处理的问题，`finally` 做资源清理。

异常不要一律吞掉。能恢复就处理，不能恢复就补充上下文后继续抛出，让上层决定。

# Java > 异常与输入输出 > 受检异常和运行时异常

来源：https://fqx.lx.ci/java-map/

受检异常要求编译时处理，常见于文件和网络；运行时异常通常表示参数、状态或代码逻辑有问题。

业务项目常自定义运行时异常，再由统一异常处理器转换成明确的错误码和提示。

# Java > 异常与输入输出 > IO：字节流和字符流

来源：https://fqx.lx.ci/java-map/

图片、压缩包等二进制数据用字节流；文本用字符流，字符流会处理编码。

读写完成后必须关闭资源，优先用 `try-with-resources`，它会自动关闭文件、连接等资源。

# Java > 异常与输入输出 > 文件处理不要一次全读进内存

来源：https://fqx.lx.ci/java-map/

小文件可以一次读取，大文件应使用缓冲和流式处理，否则文件多大就可能占用多少内存。

这条规律也适用于网络响应和数据库结果：数据量不确定时，要分页或边读边处理。

# Java > 异常与输入输出 > 对象怎样变成可传输的数据

来源：https://fqx.lx.ci/java-map/

对象只存在于 JVM 内存里，跨网络或保存到文件前要序列化，Web 项目最常用 JSON。

DTO 用来定义接口传输的数据结构，不要直接把数据库实体原样暴露给外部。
