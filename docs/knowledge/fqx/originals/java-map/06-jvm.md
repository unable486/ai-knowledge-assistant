# Java > JVM 怎么管理程序

来源：https://fqx.lx.ci/java-map/

类加载器把字节码放进 JVM，线程栈记录方法调用，堆保存对象，GC 清理不再使用的对象。理解这条线，就能看懂常见的内存问题。

# Java > JVM 怎么管理程序 > 类加载：用到类时把它加载进来

来源：https://fqx.lx.ci/java-map/

JVM 读取 `.class` 字节码，校验并创建对应的类信息，然后执行静态初始化。

双亲委派让核心类优先由上层加载器加载，避免项目自己写一个同名 String 破坏基础运行环境。

# Java > JVM 怎么管理程序 > 栈、堆和元空间

来源：https://fqx.lx.ci/java-map/

- **栈**：每个线程私有，保存方法调用和局部变量
- **堆**：线程共享，保存对象，是 GC 的主要区域
- **元空间**：保存类的结构信息

递归太深常导致栈溢出；对象长期被引用可能撑满堆。

# Java > JVM 怎么管理程序 > GC：回收不可达对象

来源：https://fqx.lx.ci/java-map/

GC 从一组根对象出发查找仍能访问到的对象，访问不到的才可以回收。

所以 Java 仍会内存泄漏：如果静态集合、缓存或监听器一直持有对象，GC 会认为它们还在使用。

# Java > JVM 怎么管理程序 > 常见内存问题怎么看

来源：https://fqx.lx.ci/java-map/

`StackOverflowError` 多半是无限递归；`Java heap space` 多半是对象太多或一次加载数据太大；频繁 Full GC 常表现为整个服务周期性卡顿。

排查时先保留日志和堆转储，再找“什么对象最多、被谁引用”，不要先盲目调大内存。

# Java > JVM 怎么管理程序 > 为什么 Java 越跑越快

来源：https://fqx.lx.ci/java-map/

JVM 先解释执行字节码，再由 JIT 把频繁执行的热点代码编译成本机机器码。

这让 Java 同时拥有跨平台和较高运行性能，也意味着启动后的预热阶段与稳定运行阶段性能可能不同。
