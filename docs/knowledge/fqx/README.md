## 文件与来源

- `originals/`：完整原文 Markdown。保留正文、代码、表格、追问、版本声明及网页地址；没有把网站观点改写成项目规则。
- `index/`：实际导入知识库的文本。标题包含语言、模块和知识点，便于区分相似主题。
- [manifest.json](manifest.json)：每份资料的原网址、节点 ID、文件路径、SHA-256、切块数量。
- [adaptations.json](adaptations.json)：45 个超长单元的分段记录。完整原文仍在 `originals/`；代码续段带有片段编号，不能单独当成完整示例运行。表格续段保留表头。
- [retrieval-check.json](retrieval-check.json)：真实本地索引上的 12 条检索抽查、预期证据和实际前四条结果。
- [export-audit.json](export-audit.json)：原文逐字、代码逐行、表格、行内代码及文件哈希的独立完整性核对。

五个知识地图从页面引用的数据文件中静态提取 Markdown；下载的 JavaScript 没有被执行。面试题从静态 HTML 提取，180 个代码块逐字符核对，包括实体解码与空白。地图中的 359 个代码块也保留在完整原文中。

地图节点使用 `data-id`，没有伪造网页锚点；通过页面 URL、标题路径和清单节点 ID 定位。面试题使用网站现有的 `#qN` 地址。

这是一次快照导入，**不会自动同步网站后续更新**。网站版本说明按原文保留，不代表本项目使用相同版本。原站个别面试页把下一节导言放在上一题答案末尾，导出保留其文字与顺序。

## 在本地知识库中使用

本次已通过项目的 `/api/documents` 接口导入。加上原有的“报销与端口说明”，当前知识库共有 **42 份文档、1,987 个片段**。打开项目后刷新页面，即可在左侧知识库看到以 `fqx ·` 开头的资料。

本地索引、导入记录和备份位于 `data/`，该目录不提交 Git。换电脑或重新建立索引时，在项目根目录执行：

```powershell
# 首先启动服务；需要已有本地 embedding 权重，见 ../../rag.md
npm run dev

# 在另一终端检查所有原文/索引哈希及 512-token 限制
node --import tsx scripts/import-fqx.ts

# 预检通过后导入当前快照
node --import tsx scripts/import-fqx.ts --apply
```

脚本使用现有切块器、模型 tokenizer 和文档 API，不调用生成模型。首次入库前把原索引备份到 `data/backups/before-fqx-*.json`；入库记录在 `data/fqx-import.json`。重复执行会跳过已导入的相同快照，不删除原有文档。若内容哈希变化或同名文档来源不明，脚本停止并提示核对。

## 验证结果与限制

- 41 份文档全部通过哈希、实际 tokenizer、现有切块器和 API 入库验证；最终片段最大为 511 token。
- 重复导入验证：新增 0 份，跳过 41 份，无重复文档。
- 原有文档及两个向量片段与入库前备份完全一致；没有 GIS 文档。
- 12 条自然问法中，9 条同时命中指定来源和全部预期关键词。其余 3 条的完整结果保存在抽查报告中：Python 可变默认参数、Node 大文件背压、Agent 重复动作。
- 人工复核发现 Python 题已经从面试资料召回等价答案，示例变量名是 `bucket` 而非用例指定的 `target`；按语义覆盖计为 **10/12**。Node 背压和 Agent 循环约束确实未出现在前四条，是后续检索排序优化的具体样本。
- 导入成功不等于任意问题都能排到正确片段。现有检索只取前四块，相近主题仍会竞争名次；以上抽查不代表生成回答准确率，本次没有调用在线生成模型。
