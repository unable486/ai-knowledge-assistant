# Java > 线程与并发

线程让一个进程同时推进多项任务。只要多个线程共享并修改同一份数据，就可能互相覆盖，因此并发的重点不是“开线程”，而是管理共享状态。

# Java > 线程与并发 > 进程、线程和任务

进程是正在运行的程序，线程是进程里的执行路线。一个 Java 进程里可以有多个线程，共享堆中的对象，但每个线程有自己的调用栈。

日常开发更应该提交“任务”，而不是手动创建和管理 Thread。

# Java > 线程与并发 > 线程安全问题从哪里来

多个线程同时读改同一个可变对象时，执行顺序不确定，就会出现丢数据、重复处理或读到旧值。

最简单的规避方式是：**少共享、少修改**。优先使用局部变量、不可变对象和数据库约束。

# Java > 线程与并发 > synchronized 和 volatile

`synchronized` 让同一时刻只有一个线程进入关键代码，既保证互斥也保证可见性。`volatile` 只保证其他线程能看到最新值，不保证 `count++` 这类复合操作的原子性。

需要计数时可使用 AtomicInteger，高并发容器用 ConcurrentHashMap。

# Java > 线程与并发 > 线程池：限制并发数量

线程创建有成本，线程太多还会争抢 CPU 和内存。线程池复用线程，并用队列承接暂时来不及处理的任务。

要关注四件事：核心线程数、最大线程数、队列容量、拒绝策略。生产环境不要使用无界队列。

# Java > 线程与并发 > 异步不是更快，而是不原地等待

`CompletableFuture` 可以组合多个异步任务，但异常、超时和线程池必须明确处理。

异步适合等待 IO；CPU 密集任务仍受 CPU 核数限制。不要把所有代码都改成异步。
