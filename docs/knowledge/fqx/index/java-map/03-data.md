# Java > 常用数据与集合

单个对象解决“一条数据”，数组和集合解决“一组数据”。集合是日常开发最常用的容器，泛型负责约束容器里装什么类型。

# Java > 常用数据与集合 > String：最常用的对象

`String` 表示字符串，而且**不可变**：每次拼接都会产生新字符串。少量拼接直接用 `+`，循环中大量拼接用 `StringBuilder`。

比较字符串内容要用 `equals`，不要用 `==`。

# Java > 常用数据与集合 > 数组：长度固定的一组数据

数组创建后长度不能改变，按下标访问很快。它适合数量已知、结构简单的数据。

当数据会不断增删，或者需要按 key 查找时，就该使用集合。

# Java > 常用数据与集合 > List、Set、Map 各解决什么问题

- **List**：有顺序、可重复，默认选 ArrayList
- **Set**：元素不重复，常用 HashSet
- **Map**：key 对应 value，常用 HashMap

选择时先问业务需要顺序、去重还是键值查找，不要先背实现类。

# Java > 常用数据与集合 > 泛型：规定容器里装什么

`List<String>` 表示这里只能放字符串。泛型把类型错误提前到编译期，也省去取值后的强制转换。

可以把它理解成：**给类和方法增加一个“类型参数”**，让同一套代码安全地处理不同类型。

# Java > 常用数据与集合 > 遍历和 Stream

普通 `for` 适合有步骤、有状态的处理；Stream 适合过滤、转换、汇总这类数据流水线。

Stream 提高的是表达力，不是一定更快。逻辑简单就用循环，别为了链式写法把代码变难懂。

# Java > 常用数据与集合 > 时间与金额要用专门类型

时间优先用 `LocalDate`、`LocalDateTime`、`Instant`，不要用字符串到处传。金额用 `BigDecimal`，不要用浮点数。

原因相同：重要业务数据要用能表达规则的类型，避免精度和时区问题。
