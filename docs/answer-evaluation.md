# 引用与回答评测基线

当前目标是分别验证“找到证据”“能核查引用”“回答是否忠实”。前两项已完成离线与页面验证；真实生成抽检被上游余额不足阻断，回答忠实度、拒答质量和引用准确率尚未验证。

## 如何运行

```bash
npm test
npm run build
npm run eval:skills
npm run eval:retrieval
npm run eval:answers
```

`eval:answers` 默认处理全部 28 题，使用本地 embedding，不调用生成 API。
语料在独立进程的内存索引中构建，不读取或覆盖用户的 `data/rag-index.json`。
首次运行前需要准备 embedding 权重，见 [RAG 说明](rag.md)。
报告输出到 `reports/answer-evaluation.json`，该目录已被 Git 忽略。

需要核查真实回答时，使用服务端同一组 `ANTHROPIC_API_KEY`、`ANTHROPIC_BASE_URL`、`ANTHROPIC_MODEL` 配置：

```bash
# 默认从 validation 选 4 题，覆盖四类；会消耗生成服务额度
npm run eval:answers -- --live --limit 4 --output reports/answer-live-review.json

# 单独复查一个样本；不加 --live 时仅检查检索证据
npm run eval:answers -- --case version-05 --output reports/version-05.json
```

`--limit` 范围为 1–28；`--case` 指定单题时优先于 `--limit`。
真实生成串行执行，每次最多输出 768 token、超时 30 秒、SDK 自动重试关闭。
任一题的检索或生成失败后停止，保留已经完成的结果和错误，报告标为 `complete: false`，进程非零退出。
`selectedCaseIds` 记录计划运行的样本，便于区分未执行和已失败。
未开始逐题评估前的配置、语料初始化错误只会退出并打印错误；报告写盘本身失败也不会生成新报告。

## 语料与标注

[answerDataset.ts](../server/rag/answerDataset.ts) 中的题目和版本规则是手写场景数据，**不是收集到的真实用户问题**。
共 16 篇文档、28 道题：

| 类型 | 题数 | 核查目标 |
|---|---:|---|
| 可答 | 10 | 关键事实能否从原文找到 |
| 无答案 | 8 | 区分明显无关和主题相关但缺少事实 |
| 多轮追问 | 5 | 简单指代是否使用近期问题恢复检索上下文 |
| 版本/冲突 | 5 | 版本条件、差异，以及无法确定现行版本时是否澄清 |

每题有 `expectedAnswer` 和 `evidence`（文档标题 + 原文引句），无答案题的证据为空。
共 25 段标注引句，覆盖 20 道有证据的题。
calibration 13 题、validation 15 题；两组仍共享文档和设计者，不能视为独立外部测试。

`evidenceRecall` 同时核对文档标题及实际提供片段中的引句，忽略切块引入的空白差异。
找到同一文档的错误章节不会算命中；无标注证据的题返回 `null`，不进入召回率分母。
它只回答证据是否进入 prompt，不判断模型是否正确使用证据。

## 2026-09-27 离线结果

| 分组 | 题数 | 有标注证据的题数 | 证据召回率 | 有证据题误过滤 | 无答案题被粗筛过滤 |
|---|---:|---:|---:|---:|---:|
| calibration | 13 | 9 | 100% | 0 | 2/4 |
| validation | 15 | 11 | 100% | 0 | 2/4 |

20 道有证据题均召回全部标注引句。8 道无答案题中，4 道明显无关的问题被粗筛拦住；
另外 4 道主题相关但缺具体事实的问题仍进入生成阶段，需要模型按资料说明无法确认。
**这组结果不是 100% 回答准确率，也不是完整拒答通过率。**

当前门槛是最高向量余弦相似度 `0.45`，只决定是否使用候选资料，RRF 仍只负责排序。
即使 BM25 精确命中，向量全部低于门槛时仍会被过滤；它可能误拒未覆盖的有效问题。
换语料、embedding 模型或切块策略后都要重新评估，不能将该门槛理解成 45% 置信度。

原有 24 道单轮检索题回归保持原水平：

| 模式 | Recall@4 | MRR | nDCG@4 |
|---|---:|---:|---:|
| vector | 91.7% | 0.917 | 0.917 |
| keyword | 95.8% | 0.917 | 0.928 |
| hybrid | 100% | 0.979 | 0.985 |

## 真实生成与人工核查

最初执行 `--live --limit 4` 时，第一题即返回 `403 INSUFFICIENT_BALANCE`，随后停止；本轮没有再次调用真实生成。
`reports/answer-live-review.json` 中有错误和部分检索结果，但没有成功生成的回答；不能据此宣称回答通过验证。
恢复配置服务的额度后，重新运行上述小批量命令，再逐题核查：

1. 对照 `expectedAnswer` 与 `sources[].excerpt`，确认每个关键结论受原文支持，没有编造数值、人员或日期。
2. 检查编号是否指向支持该结论的片段。`unknownCitationIds` 只能找不存在的编号，合法编号仍可能引用错段。
3. 无答案时应说明缺少什么依据；版本冲突时应分别引用、保留适用条件，不得假定“最新版本必然现行”。
4. 检查 `stopReason`；输出被截断、拒绝或失败时，不能按完整回答判为通过。

真实回答初始标记 `manualReview: "pending"`，脚本不会自动把检索命中或编号合法判成回答正确。
下一步应先完成这轮人工核查，再用真实失败问题扩充语料，而不是仅根据现有满分召回率继续调参数。

## 回归与页面验证

最初的 22 项回归覆盖上下文预算、写盘失败与并发、引用快照和旧记录兼容、
原文安全展示、预算边界、追问扩展和不存在的引用编号。当前 `npm test` 共 52 项通过，
新增结构切块、真实 token 预算保护、技能选择/参考资料/冲突/路径边界和前端重试等回归；`npm run build` 通过。
`npm run eval:skills` 的 12 个手写路由与按需参考场景通过，原 24/28 题指标保持。
技能运行方式和证据边界见 [项目技能](skills.md)；这些检查不证明模型已正确遵循技能。

浏览器使用临时模拟 SSE 服务验证了引用折叠、原样展示 HTML 字符、刷新后保留原文，
以及资料不足时无来源卡片、检索面板明确显示未使用资料。这是前端展示验证，不是模型生成验证。
